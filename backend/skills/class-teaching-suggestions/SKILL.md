# 班级简明教学建议

## 输入与依据

输入是已经确认来源的精准教学情境与 `level_needs`，含当前非空层级、人数、上游障碍和相邻进阶目标。只处理输入中的层级，不虚构学生、人数或障碍，不改动上游层级。

生成前完整阅读 `references/thesis-progression-rules.md`。它提炼自教师提供的论文材料，是内容、活动和支架选择的依据。材料中的参考文献不需要在教师页面重复罗列，也不自行补造来源。

## 生成规则

每个非空层级一条建议，按P、U、M、R、EA排序，字段为：

- `level`：输入当前层级。
- `target_level`：相邻目标，P→U、U→M、M→R、R→EA、EA→higher_EA。
- `development_goal`：下一步可观察的认知变化，结合教师关注的主题和目标，不只是改写层级定义。
- `content`：选什么具体材料、概念、案例或条件；不能只写“基础内容”“更多材料”。
- `activity`：学生做什么简短加工并产生什么表现，例如比较两种方法的适用条件并说明选择。给一个教学思路即可，不展开实施步骤、时间表或新题完整答案。
- `scaffold`：给什么最小必要支持；可用图示、提示卡、空白比较表或AI追问。支持应逐步撤除，不替学生作答或建立关系，也不强行为每行使用AI。

先看真实障碍与共同目标，再据进阶方向选择内容/活动/支架。相同活动可采用不同支持，不为“分层”机械安排完全不同的课。

每格优先15—35个汉字，一句话，最多60字符；每层四格合计最多180字符。避免重复主题全称、讲理论、写鼓励套话、逐个学生单列或完整教学方案。建议是待教师选择的教学思路，不是已实施活动或已证实效果。

## 输出与检查

仅输出符合 `assets/teaching-suggestions.schema.json` 的JSON。`items`必须恰好覆盖输入的非空层级，无重复、无遗漏。人数与来源状态由平台添加，不由模型输出。若无真实诊断或主题目标缺失，平台应拒绝生成，不能用通用模板伪装AI结果。
