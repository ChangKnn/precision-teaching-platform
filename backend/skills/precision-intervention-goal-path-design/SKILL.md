# 精准干预目标与课堂路径设计

## 任务边界

完成两项设计：

1. 从课程标准、教学要求和精准教学内容中形成共同核心目标，再依据班级诊断生成分层进阶目标；
2. 推荐课堂主要路径，并把全班、小组、个体、学习站或综合应用安排为可实施的顺序阶段和并行活动单元。

不得修改上游学生SOLO层级，不得用任务难度代替认知结构差异。不要生成具体任务文本、操作步骤、逐字话语、详细支架、形成性评价设计、干预成效评价工具或完整教案。

## 输入门槛

运行前按照 [输入schema](assets/goal-path-input.schema.json) 检查：

- `precision_teaching_context`：精准教学的学科、年级、教材、主题、目标和内容；
- `diagnosis_bundle.class_diagnosis`：上游班级SOLO聚合诊断，必需，其中 `intervention_design_basis` 提供面向学生、诊断发现、认知变化和设计条件；
- `diagnosis_bundle.task_specific_solo_rubric`：可选，用于理解当前任务中的层级含义；
- `diagnosis_bundle.student_diagnosis_results`：可选，只用于核对学生、层级和主要障碍，不得重新定级；
- `teacher_instructional_context`：教学内容与课标分析、教学重点与难点分析、教学时长、教学环境与AI支持条件，以及可选的课堂教学设计构想。前两项由平台AI辅助生成、教师修改确认后传入；后三项由教师填写，其中课堂构想可留空。
- 重新生成时还会收到 `teacher_revision_request` 与 `previous_goal_path_design`：前者是教师本轮提出的修改要求，后者是上一版（可能经教师编辑）的方案。

若缺少必需字段、学生总数与名单不一致、同一学生出现多个当前层级，或上游 `levels_unchanged` 不为真，停止并说明问题。班额从班级诊断自动读取，不要求教师重复填写。平台必须在教师确认或修改两项AI辅助分析后再调用本Skill。教师实施条件缺失时不得伪造；只有用户明确要求试运行时，才可使用清楚标注的测试假设并列入待确认项。

## 执行流程

### 1. 锁定语境与诊断结果

读取精准教学主题、目标、内容以及教师确认的教学分析和实施条件。锁定上游每名学生的SOLO层级、主要表现和进阶障碍，并读取 `intervention_design_basis` 中的面向学生、认知变化与设计条件。教师课堂构想不是装饰性背景：若非空，先提取其中的学习起点、情境/认知冲突、学习方法、组织安排和支持设想，再判断哪些可在本课时与诊断约束下实施；把可实施部分落实到具体活动名称或内容简介，不能仅在推荐理由中复述。明确标注“必须保留”的内容视为不可协商要求；与时长、资源或诊断明显冲突的构想列入教师待确认事项，不暗中忽略。不得把构想扩写为未经教师提供的具体题目或操作步骤。

若收到教师本轮修改要求，逐项对照上一版方案，仅重做要求涉及的内容，尽量保留未被要求修改且仍正确的教师编辑。修改要求不能推翻学生原始诊断、名单唯一归属、课时总长和输出结构；若要求冲突，在 `teacher_confirmation.unresolved_decisions` 中说明取舍，不能默默忽略。不要把上一版的旧命名、错误目标映射原样带入新方案。

### 2. 生成共同核心目标

完整阅读 [目标设计规则](references/goal-design-rules.md)。共同核心目标首先来自课程标准、教材内容和教学要求；班级诊断只用于判断学生与目标之间的距离，不得降低课程目标。

教师端只输出：

- 核心目标；
- 目标认知结构及理由；
- 可观察的达成表现。

不得显示课程依据、诊断依据、目标边界或目标追溯报告。

### 3. 生成分层进阶目标

按照当前层级、主要障碍和下一步认知变化聚合学生。默认采用相邻Plus One；已达到共同目标的学生仍需获得迁移或EA深化目标。

教师端只使用四列表格：

`目标层级 | 具体目标内容 | 相关学生姓名 | 可观察的达成表现`

每名学生必须恰好归属一个主要进阶目标。机器结果只保留目标层级、面向层级、学生、目标内容和可观察表现，不重复复制诊断依据或认知变化说明。下游Skill需要诊断信息时，由编排智能体继续传递原始 `diagnosis_bundle`。

### 4. 推荐主要路径与备选路径

完整阅读 [路径选择规则](references/path-selection-rules.md)，先选择主要课堂组织方式，再构造课堂阶段。

必须联合使用：

1. 学生差异形态；
2. 共同目标和进阶目标结构；
3. 教学内容的前后依赖、并行加工或模块拆分关系；
4. 总时长、班额、资源、技术和教师管理负荷。

可选组织模式为递进推进型、主线嵌入型、并行分层型、站点轮转型、个体自驱型。模式可以单独使用，也可以由两个模式组合使用。组合模式最多包含两个类型，其中“递进推进型”说明课堂整体按前后阶段逐步深化，另一类型说明核心阶段如何组织差异化学习。除完全并行或几乎完全个体练习的课堂外，只要存在共同定向、核心学习、汇聚应用等前后依赖阶段，均应考虑加入“递进推进型”。

若两个候选组织方案适配程度接近，除主要方案外再提供一个备选方案，说明何时更适合采用及其代价；否则不为完整而强行生成备选。

教师端把模式显示为“主要组织模式”，例如“递进推进型＋并行分层型”；不要在模式名称后重复阶段摘要。紧接着用一句“模式说明”解释该模式在本课中如何运行，再用2—4条具体事实说明推荐理由。课堂阶段的具体先后和并行关系另写为“课堂推进安排”。

### 5. 构造教师可读的课堂活动路径

课堂路径使用“阶段—活动单元”两层结构：

- 有先后依赖的活动安排在不同阶段；
- 不同学生可以同时完成的活动放在同一阶段的多个并行活动单元中；
- 同一阶段的并行活动共享内部阶段编号，例如 `ST2-I1`、`ST2-H1`、`ST2-X1`；教师端不单列编号或“阶段”；
- 阶段时长按一次计算，并行单元时长不得相加；
- 各阶段建议时长之和必须等于教师输入的总时长。

45分钟单课时原则上只安排**一个集中小组活动时段**：可在该时段内让多个同质或异质小组同时完成不同任务，但不要在后续阶段再次安排一轮小组活动。其余时段优先用于全班辨析、独立尝试、成果汇聚或应用。不能为了覆盖多个进阶目标而把一组并行任务拆成前后两次分组；确有教师明确提出的两轮分组或不可替代的教学需要时，说明额外组织转换及时间代价，并列为教师待确认，而非默认生成。多课时设计按每课时分别判断。

`stage_name` 是教师端该时段唯一的**活动名称**，应结合本课学科内容与主要学习行为命名，如“比较两种求角路径，说明选择依据”；不得写“共同定向”“分层并行加工”“共同汇聚”等组织阶段标签。同一时段有多个并行单元时，它们共用这一个活动名称；`unit.activity_name` 写各组的简短方向名，教师端放在“活动内容简介”内，不另开活动名称列。单单元时 `unit.activity_name` 与 `stage_name` 一致。教师端优先写文字组织形式，符号只放在括号中辅助识别。

每个单元的 `target_goal_ids` **恰好只有一个**：依据该单元要求学生实际完成的主要认知加工确定，而不是依据参加人数或学生当前层级。辨认一个关键对象、并列处理多个要素、建立关系、迁移检验等活动，分别判断其目标层级；若一个活动真的同时承载不同层级且无法指出主要目标，应拆成并行单元或重写活动简介。共同学习活动只有在实际推进共同核心目标时才选 `CG`，不是因为全班参加就自动选 `CG`；分组活动选择其实际推进的一个 `PG`。教师端“目标层级”显示该目标的认知结构/层级名称，而不是学生名单或笼统的“面向全体”。路径表固定包含：活动名称、组织形式、活动内容简介、目标层级、建议时长。

“活动内容简介”要让一线教师读完就能说出“学生在这个活动里做什么”。每个单元用一至三句写清：操作的本课具体对象或材料、学生要进行的可观察学习动作、预计形成的简要学习产出；并行单元先写组别方向名，再分别写本组的动作与产出。优先使用教师课堂构想中已有的情境、材料或方法，不虚构题目条件、数值与资源。避免只写“明确目标”“建构关系”“形成框架”“开展探究”等抽象意图，也不要把目标陈述原样移到简介。可以给出足以理解活动的任务轮廓，但不展开为逐步操作指令、完整题目、详细支架、师生话语或形成性评价。若缺少具体材料，使用输入中可确认的学科对象或作答证据，并将需要教师补充的材料列为待确认，不用空泛话术填充。

### 6. 形成教师确认稿

按照 [输出模板](assets/goal-path-output-template.md) 先输出教师可读Markdown，再附加标记为 `json precision_intervention_goal_path` 的有效JSON代码块。JSON必须符合 [输出schema](assets/goal-path-output.schema.json)。

教师至少确认：共同核心目标、目标认知结构、分层目标与学生归属、主要路径、备选路径（若有）、并行安排和阶段时长。教师确认前状态保持 `pending_teacher_confirmation`。

## 交付前自检

- 共同核心目标主要来自课程标准与教学要求，诊断没有降低目标；
- 教师端没有课程依据、诊断依据、目标边界或目标追溯；
- 上游SOLO层级逐生保持不变；
- 每名学生恰好对应一个主要进阶目标；
- 目标具有可观察表现，不使用“理解了”“掌握了”等模糊表述；
- 路径选择使用差异、目标、内容结构和实施条件四类信息；
- 路径类型按课堂实际组织方式判断，不把认知层级递进直接等同于时间顺序；
- 同时发生的活动共享阶段编号并以不同活动单元表示；
- 并行活动时长只计一次，各阶段时长之和等于总时长；
- 45分钟单课时默认只有一个集中小组活动时段；同一时段的多个并行小组不算多次小组活动；
- 教师端使用文字名称，符号仅放在括号中辅助表征，不另列符号说明；
- 每个时段均有结合本课内容、清楚日常的共同活动名称，并行组名只放在内容简介；
- 每个活动内容简介都明确本课具体对象、学生可观察动作和简要产出；不同组的动作与产出体现各自目标层级，不只是换组名；
- 每个活动单元只有一个主要目标层级；全班活动不因参与人数而映射所有分层目标，`CG` 和 `PG` 均对应实际认知加工；
- 教师课堂构想非空时，可实施的关键设想已落在具体活动中；未采用的重要设想已说明理由并列为待确认；
- 推荐理由前有一句模式说明，组合模式最多包含两个类型；
- 只有适配程度接近时才输出一个备选路径；
- 没有形成性评价节点、进入/退出条件或动态路由规则；
- 没有侵入后续活动细化和评价设计职责；
- 机器结果通过输出schema。
