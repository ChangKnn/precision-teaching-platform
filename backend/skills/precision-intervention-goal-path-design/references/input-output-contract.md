# 输入输出契约说明

## 输入命名

六个诊断与干预 Skill 统一使用 `precision_teaching_context` 表示精准教学背景，字段固定为学科、年级、教材版本与章节、精准教学主题、精准教学目标和精准教学内容。编排智能体直接传递该对象，不再执行字段改名或结构映射。

`teacher_instructional_context` 固定包含：

- `teaching_content_and_curriculum_analysis`：AI依据精准教学基本信息辅助生成，教师修改确认；
- `teaching_focus_and_difficulty_analysis`：AI结合精准教学基本信息和班级诊断辅助生成，教师修改确认；
- `planned_duration_minutes`：教师填写的教学时长；
- `teaching_environment_and_ai_support_conditions`：教师填写的教学环境、AI可用方式、关键资源和现实限制；
- `teacher_lesson_conception`：教师可选填写的课堂教学设计构想。

重新生成时另传 `teacher_revision_request`（教师本轮要求）与 `previous_goal_path_design`（上一版方案）。二者不混入教学条件；新生成结果应在满足诊断和结构约束的前提下按要求修订，并保留未涉及的合理教师编辑。

班级人数从班级诊断自动读取。Skill不再要求教师填写班额、资源清单、偏好、硬约束、共同经历或预选路径类型。

## 上游诊断保持

`diagnosis_bundle.class_diagnosis` 必须保持上游原始机器结果。Skill 1不得修改学生层级、ID、姓名和典型证据。

班级诊断中的 `intervention_design_basis` 是后续方案设计的决策输入，每项包含面向学生、诊断发现、需要促进的认知变化和设计条件。Skill 1据此生成目标与路径，不把它当作已经确定的课堂活动，也不得恢复已经从上游删除的详细活动建议。

Skill 1输出不重复复制诊断依据和认知变化。编排智能体必须把以下内容分别传给后续Skill：

- 原始 `precision_teaching_context`；
- 原始 `diagnosis_bundle`；
- 原始 `teacher_instructional_context`；
- Skill 1生成的目标与课堂路径。

这样，学习活动设计和评价设计直接依据原始诊断，不依赖Skill 1的二次转述。

## Skill 1输出

### 目标

以下为机器传递字段。教师界面与导出仅显示共同核心目标及括号SOLO，理由与共同目标可观察表现供下游使用，不重复展示。

- 共同核心目标；
- 目标认知结构及理由；
- 共同目标的可观察表现；
- 分层进阶目标及学生唯一映射。

### 课堂路径：字段与展示约定

教学选择与活动安排依据[path-selection-rules.md](path-selection-rules.md)，此处只约定机器结构和展示方式，保持现有Schema兼容。

- `primary_path_types`和`primary_path_label`表示主要组织模式；组合最多两个，名称用全角加号连接。`mode_explanation`解释本课怎样运行，`recommendation_reasons`用2—4条具体事实说明理由；`teacher_facing_path`表达课堂推进安排。备选仅在确有必要时填写，名称不混入整条阶段摘要。
- `stages`按时间顺序排列，`stage_id`连续使用`ST1`、`ST2`等。并行单元共享阶段，其`unit_id`按`ST2-H1`等规则唯一命名；不把它们串成顺序阶段。
- `stage_name`为本时段共用的简短学科活动名称，优先内容对象加学习动作，如“分析衰亡原因”“探究判定条件”，不写成长句；并行`activity_name`写各组/站点具体学习任务方向，放在内容简介，不使用机器目标编号命名。单单元时两个名称相同；不另列编号或阶段名称给教师。
- `organization_code`使用现有C/H/X/I/S等编码。A是应用功能：新综合应用单元按实际H/X/I编码，在名称或简介说明应用任务，不创造AH/AX等编码；保留旧A记录兼容。S的站内H/X/I方式写在简介，不添加新必填字段。
- `activity_summary`写具体内容或问题、学生主要学习动作与形成的认识/成果；在衔接处说明前段成果如何用于后段，不展开完整教案。模式依据放在说明字段，不塞入简介。
- `target_goal_ids`恰好一个，填写实际推进的`CG`或对应`PG`。按主要认知加工选择，不按参与人数或学生当前层级选择；全班活动不自动映射所有目标，也不必一律选CG。
- 活动单元不包含`target_students`或`target_student_ids`，不复制、补算或逐人校验参与者。`target_goal_ids`保留目标引用；面向全班或哪类学习群体以组织方式和简介说明，轮转安排描述学习流动，不枚举学生。分层目标仍保留真实名单与原始层级。
- `duration_minutes`按阶段填写一次，并行单元不相加；阶段总和等于`planned_duration_minutes`。单课时/跨课时范围、小组次数和转换时间遵循路径规则。
- 教师路径表固定为`活动名称｜组织形式｜活动内容简介｜目标层级｜建议时长`。优先文字名称，符号仅放括号辅助；目标层级显示所选目标的名称，不显示机器ID或学生名单作为层级。

本Skill可描述支路支持后回归、站点流动和个体修订等组织关系；不输出E评价节点、量化进入/退出阈值、评价题、详细形成性证据清单或自动分流算法，交后续活动与评价设计负责。

## 下游交接

### 给学习活动细化设计Skill

- 已确认的共同核心目标；
- 分层进阶目标及学生映射；
- 路径类型、阶段、并行活动单元和建议时长；
- 教师教学条件和硬约束；
- 原始班级诊断。

### 给形成性诊断与干预评价设计Skill

- 共同目标和分层目标的可观察表现；
- 课堂阶段和活动单元；
- 学生起点层级；
- 原始班级诊断。

评价Skill自行确定评价位置、证据任务和调节规则，不由Skill 1预设E节点。

### 给方案整合与一致性检查Skill

- 目标—学生唯一映射；
- 主要路径、备选路径、阶段和时长；
- 教师确认状态和未决条件；
- 原始输入及其他Skill输出。

## 版本与确认状态

- 初次生成：`pending_teacher_confirmation`；
- 教师明确确认后由编排智能体改为 `teacher_confirmed`；
- 教师修改目标、学生归属、路径或时长后，应触发相关下游内容重新生成或检查。

## 平台输出格式

首次生成返回`goal-path-output.schema.json`规定的完整目标路径JSON。已有方案修改只返回`{"changes":[{"path":"/intervention_path/stages/0/stage_name","value":"案例导入"}]}`，只替换教师要求涉及的已有字段；新值直接使用JSON类型，不二次编码为字符串。程序合并原稿后用完整Schema校验。当前请求附带的Schema决定本次输出形式。不包装额外文字报告，不输出Markdown代码块。平台校验、还原真实姓名后生成教师可读报告；首次生成、编辑保存与导出共用排版逻辑。

所有学段的小组活动安排统一依据路径规则，不在运行时另设45分钟或大学例外。跨级/自定义目标是教师可作的设计调整，仍保留真实诊断及名单，不新增教师必填理由。

`common_core_goal.goal_statement`只保存目标正文，不附SOLO层级；层级来自`target_cognitive_structure`，平台在文字末尾只显示一次。目标设计与课堂活动路径设计使用明显的主标题；模式、理由和推进说明放在路径表下方的“课堂活动路径设计说明”中，页面默认折叠，教师可展开查看。

教师确认只展示`unresolved_decisions`中的具体未决事项；无事项不显示。兼容字段`items_to_confirm`可留空，不要求通用清单。页面与文字报告使用同一规则。
