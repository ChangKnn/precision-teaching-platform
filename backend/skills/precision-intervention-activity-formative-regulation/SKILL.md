# 学习活动与形成性评价设计

## 任务定位

本 Skill 承接 `precision-intervention-goal-path-design` 已经由教师确认的结果，完成两项工作：

1. 将课堂路径中的活动单元细化为教师可直接组织的学习活动；
2. 仅在需要作出教学决策的位置，设计形成性评价及评价后的教学调整。

教师端结果必须简洁，只呈现实施所需的核心信息，使用一线教师熟悉的语言。

## 职责边界

- 不重新判断或修改学生的 SOLO 层级。
- 不修改上游共同目标、分层进阶目标、学生—目标对应关系、阶段顺序和总时长。
- 不为每名学生分别生成一套教案。
- 不为了体现 AI 而机械加入 AI。
- 不把形成性评价变成每个活动后的额外测验。
- 不负责干预结束后的成效评价，也不负责完整方案合并与检查。

## 输入门槛

开始设计前，按照 [输入输出契约](references/input-output-contract.md) 检查：

- `precision_teaching_context`；
- `diagnosis_bundle`；
- `teacher_instructional_context`；
- `goal_path_design`，且设计状态和教师确认状态均为 `teacher_confirmed`；
- 可选的 `teacher_activity_requirements`。

如果上游路径尚未确认，停止设计并请教师先确认。教师若要改用备选路径，应先让 Skill 1 更新目标与路径结果，而不是在本 Skill 中自行改路。

`teacher_instructional_context` 使用统一五项结构：教师已确认的教学内容与课标分析、教学重点与难点分析，教师填写的教学时长、教学环境与AI支持条件，以及可选的课堂教学设计构想。班额从班级诊断读取。教师构想中明确标注“必须保留”的内容不得擅自删除。

## 工作流程

### Step 1：锁定上游约束

提取并保持以下信息不变：目标编号、学生编号、阶段编号、活动单元编号、阶段时长和总时长。记录每个活动单元对应的目标、学生、路径功能与活动内容简介。上游的“综合应用”“学习站”等路径功能不得直接当作组织形式。

### Step 2：细化活动单元

教师端的“活动”按课堂实际推进顺序编号，不按并行小组数量编号：

- 一个阶段只有一个活动单元时，通常生成一项活动；
- 同一阶段的多个活动单元同时开展时，合并为一项“分组并行活动”，在同一张表内分别说明各组目标、任务、支架和产出；不得把同时发生的小组任务写成活动2、活动3、活动4；
- 同一单元内部确有两个需要先后完成的独立任务时，才可拆成连续子活动，且保持原阶段、目标、学生、组织形式和时长总和。

每项活动单独使用一张教案式活动表。活动名称不放入表格，单独写在表格上方，格式为：`活动X：活动名称（时长；组织形式）`。若并行小组采用多种组织形式，括号内按实际列出。

依据 [学习活动设计规则](references/activity-design-rules.md)，为每项活动确定：

- 学生要完成的具体任务；
- 任务要求的核心思考；
- 必要的差异化支架及撤除条件；
- 可观察的学习产出。

再根据活动目标、学生差异、互动需要和课堂条件，从以下四类中选择最合适的组织形式：全班集体干预、同质小组干预、异质小组干预、个体干预。不得输出其他组织形式。“综合应用”只用于说明活动目标或任务功能。

### Step 3：设计主体活动与会话圈

依据 [会话圈规则](references/conversation-circle-rules.md)，先按组织形式选择允许的会话圈类型，并保留在机器 JSON 中。教师端不单列“会话圈”或“会话圈交互过程”，而是在“活动过程”内部设置三个二级栏目：教师活动、学生活动、AI辅助。

- 教师活动：按课堂实施顺序写教师提供材料、明确任务、观察指导、组织交流和作出专业判断的关键动作；
- 学生活动：写学生独立、小组或全班完成的认知加工与操作，同伴互动一并写入此栏；分层并行活动可在此栏按组分项；
- AI辅助：只写具有明确增益的即时追问、比较、反馈或材料处理；没有必要使用AI时留空。

三个栏目属于“活动过程”的内部结构，不得写成整张活动表的统一表头。每栏只保留教师实施所需的信息，不写逐字话术。

只有在 AI 能提供即时比较、追问、反馈或材料处理，且不会替代学生思考与教师判断时，才安排 AI。若教师条件不支持 AI，则改为教师、同伴或学习材料承担相同功能。

### Step 4：设置形成性评价

依据 [形成性评价规则](references/formative-evaluation-rules.md)，只在以下情形设置评价：

- 学生是否可以进入下一阶段；
- 是否需要更换或减弱支架；
- 分层活动是否可以汇合；
- 是否需要调整组织方式或支持主体。

单节课通常安排1—2次形成性评价；多课时方案一般按每课时1—2次控制。优先使用活动自然产生的作答、解释、作品、讨论或生机会话作为证据。每次评价必须给出：评价时机、对象与目标、评价任务与证据、达成标准、不同结果的处理，以及最终判断主体。教师端“评价时机”只写“活动X之后”，不重复活动名称、阶段名称或长句说明。

形成性评价汇总表必须适合课堂上快速扫读：每个字段只写判断和行动所需的最少信息，避免整段解释。对象与目标点明本次要看的表现；任务与证据各一句短语；每个层级的“达到/尚未达到”各写一条可观察的关键差别；三种结果处理各写一个当场可执行动作。建议单条标准或处理不超过约40个汉字；宁可分清关键差别，也不要把多个要求串成长句。不要在多列重复学生名单、目标全文、活动背景或理论解释。需保留的完整依据可留在机器结果中，不塞进表格文字。

每个评价节点只纳入本次教学决策真正需要判断的目标，不因班级有五个层级，就在每个节点机械列出五套“达到/未达到”。确需覆盖全部层级时，先写一条共同的证据与处理原则，再让各层标准只点出各自独有的关键差别，避免整套目标重复五遍。

### Step 5：校核课堂可实施性

检查：

- 各阶段活动时长与 Skill 1 一致；
- 同一阶段并行活动可以在现有教师、空间、材料和设备条件下管理；
- 支架数量和形式不过度增加教师负担；
- 每个活动都有清晰学习产出；
- 单节课形成性评价通常为1—2次，评价后的调整能在课堂中立即执行。

### Step 6：生成结果

按照 [教师端输出模板](assets/activity-formative-output-template.md) 输出：

1. 每项顺序活动使用一张无整表表头的教案式活动表；活动名称、时长和组织形式写在表格上方；
2. 表格只保留活动目标、活动过程、学习材料与资源、学习产出四个一级项目；活动过程内部按教师活动、学生活动、AI辅助三列呈现；
3. 在支持合并单元格的文档中，活动目标、学习材料与资源、学习产出三行的右侧三个单元格横向合并，活动过程左侧单元格纵向合并；
4. 活动目标必须承接Skill 1已确认的共同核心目标或分层进阶目标，并转化为本活动中的具体内容和可观察表现；上游 `target_goal_ids` 中 `CG` 指共同核心目标，`PG` 指对应进阶目标，须原样承接，不能因全班参与就扩展为全部 `PG`；括号内标注对应的SOLO层级或进阶方向；不得新增、降低或跨越上游目标；
5. 一张形成性评价汇总表，单节课通常1—2行；
6. 待教师确认事项；
7. 供下游 Skill 使用的机器可读 JSON（`schema_version = 1.3`）。

同一阶段存在多个并行单元时，在活动目标、学生活动和学习产出中按组分别说明；教师活动或AI辅助确有分组差异时再分组说明。组织形式只使用四种标准名称；会话圈只使用规则表中的标准名称并保留在机器结果中。教师端正文不呈现会话圈名称、AI内部设计提示、理论论证、诊断追溯、长篇说明或逐字稿。机器 JSON 保留全部上游单元编号、会话圈和映射关系。

## 质量检查

提交前必须确认：

- 教师能够通过活动标题和活动表看清时长、组织形式、目标、教师活动、学生活动、AI辅助、材料资源和学习产出；
- 教师活动、学生活动、AI辅助只作为“活动过程”的三个二级栏目，不得成为整张表的统一表头；
- 活动名称、时长和组织形式位于表格上方，不在表格中重复；
- 活动目标能够追溯到Skill 1已确认目标，并转化为本活动中的具体可观察目标；
- 并行小组只占一个活动序号，并在该活动内部逐组说明；
- 组织形式仅出现全班集体干预、同质小组干预、异质小组干预、个体干预；“综合应用”等功能词只写入目标或内容；
- 机器结果中的会话圈名称与组织形式匹配，教师端不单列会话圈；
- 活动目标能追溯至 Skill 1 的目标编号；
- 活动中的学生范围不超出上游活动单元；
- 任务与支架真正针对相应的认知进阶，而不是换一种说法重复目标；
- M→R 明确要求建立关系，R→EA 明确要求概括、迁移、条件或边界分析；
- 三类主体活动呈现关键实施动作，不写对话脚本；同伴行动归入学生活动；
- 教师端不出现“设计提示”“设计要素”“输出内容”等生成过程用语；
- AI 使用具有必要性和条件性；
- 单节课通常只设置1—2次形成性评价；评价标准描述可观察表现，不以答案长度、关键词数量或 SOLO 标签替代标准；
- 形成性评价表各单元格简短且不重复；每条标准和处理用一句话说清关键判断或动作；
- 未在本 Skill 中重新定级学生；
- 教师端文字短、具体、可执行。
