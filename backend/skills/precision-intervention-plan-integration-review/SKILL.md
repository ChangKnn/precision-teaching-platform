# 精准干预方案整合与检查

## 目标

输出两部分：

1. 一份语言简洁、表格化、可直接用于备课的精准干预方案；
2. 一张只包含八项结果的简短审核表。

本 Skill 是整合者与审核者，不是新的方案设计者。

## 必需输入

- `precision_teaching_context`：精准教学背景；
- `teacher_instructional_context`：AI辅助、教师确认的教学分析及教师填写的教学情境与条件；
- `diagnostic_task_context`：教师设计的诊断任务原文、作答方式和可选来源引用；
- `class_diagnosis_result`：班级 SOLO 聚合诊断结果（兼容 `1.0` 与 `1.1`，输出须标记真实输入版本）；
- `goal_path_design`：Skill 1 已确认的目标与路径设计；
- `activity_formative_design`：Skill 2 已确认的学习活动与形成性评价设计；
- `integration_preferences`：可选的标题、教师、日期和姓名显示设置。

处理字段、兼容版本和机器输出时，读取 [references/input-output-contract.md](references/input-output-contract.md)。生成教师方案时，使用 [assets/teacher-facing-output-template.md](assets/teacher-facing-output-template.md)。

三个背景对象必须各司其职：

- `precision_teaching_context` 只保存学科、年级、教材版本与章节、精准教学主题、目标和内容；
- `teacher_instructional_context` 只保存教学内容与课标分析、教学重点与难点分析、教学时长、教学环境与AI支持条件，以及可选的课堂教学设计构想；
- `diagnostic_task_context` 只保存诊断任务及其来源信息。

这些字段构成跨 Skill 的统一字段字典。当前 Skill 必须使用本任务所需字段，但不得把某一对象中的字段改名、移入另一个对象或自行创造同义字段。

## 不可突破的边界

- 不重新判断或修改学生的 P、U、M、R、EA 层级。
- 不改变 Skill 1 已确认的共同目标、分层目标、学生归属和主要路径。
- 不改变 Skill 2 已确认的活动实质、支架、会话圈、评价标准和时长。
- 只允许压缩重复文字、统一术语、调整表格和把内部 ID 换成教师可读名称。
- 不输出新的“干预成效评价”。形成性评价仍随 Skill 2 结果纳入方案。
- 发现实质冲突时，明确指出应退回诊断 Skill、Skill 1、Skill 2，还是请教师补充条件；不得静默修正。

## 工作流程

### 1. 锁定输入版本与确认状态

核对班级诊断、Skill 1 和 Skill 2 的版本。Skill 1 或 Skill 2 未经教师确认时，可以形成草案和审核意见，但不得把方案标记为“可直接使用”。

### 2. 建立机器对应链

建立并保存：

`诊断表现与障碍 → 分层进阶目标 → 路径节点 → 学习活动 → 学习产出 → 形成性评价`

该对应链只用于检查。教师正文不显示内部追溯链和机器 ID。

### 3. 执行八类审核

完整读取并执行 [references/review-rules.md](references/review-rules.md)。八类检查不得拆成几十条对教师展示。

每类只能给出一种状态：

- `✓ 通过`：设计合理，无需调整；
- `△ 建议优化`：不影响整体实施，但存在可优化点；
- `× 需要修改`：存在目标、活动、路径或实施方面的明显冲突。

整体状态按最严重结果确定：

- 八项均为 `✓ 通过` → `ready_for_use`；
- 没有 `×`，但至少一项为 `△` → `ready_with_suggestions`；
- 任一项为 `×` → `needs_revision`。

### 4. 生成教师版方案

严格按以下顺序呈现：

1. 精准教学基本信息；
2. 学生诊断结果；
3. 教学情境与条件；
4. 精准干预目标；
5. 学习活动设计；
6. 形成性评价；
7. 方案审核结果。

使用多个紧凑表格，不把全部信息挤进一个超宽总表。学生诊断应先以一个“诊断任务”区块完整复制上游“诊断任务设计”的教师可读内容，再呈现分布、典型表现、主要障碍和班级诊断总述。不要把任务内容、任务材料、作答方式和任务要求拆成多个教师端字段；它们都属于同一个诊断任务。保留上游已有来源链接；没有链接时不额外生成“原任务与材料”字段，也不得虚构链接。

班级诊断总述必须用一个连贯段落覆盖四项信息：

1. 分布特点与层级差异；
2. 班级已有学习基础；
3. 共同障碍与不同层级的主要障碍；
4. 下一步教学方向。

精准干预目标只整合 Skill 1 的精简结果。Skill 1 的总体路径和教师的课堂教学设计构想仅作为内部整合与一致性审核依据，不在教师版方案中展示。分层进阶目标表后必须原样保留以下说明：

> **说明：** 表中“目标层级—面向学生”的对应，是依据当前诊断为学生确定的最近发展目标，用于安排差异化支持；并不表示学生在本节课中只能达到该层级。学生达到当前目标后，可以继续向更高层次进阶，教师应根据形成性评价动态调整目标与支持。

### 5. 整合学习活动

每个顺时活动单独呈现。活动名称不放入表格，标题固定写为：`活动X：活动名称（时长；组织形式）`。

活动表不设置整表表头，只保留四个一级项目：

- 活动目标；
- 活动过程；
- 学习材料与资源；
- 学习产出。

“活动过程”内部设置教师活动、学生活动、AI辅助三个二级栏目。三者不得成为整张活动表的表头。同伴活动归入“学生活动”；AI没有明确增益时，“AI辅助”留空。会话圈仅用于机器检查，不在教师版方案中单列。

在支持合并单元格的Word或HTML中，活动目标、学习材料与资源、学习产出三行的右侧三个单元格横向合并，活动过程左侧单元格纵向合并。

活动目标承接Skill 1已确认的共同核心目标或分层进阶目标，由Skill 2结合具体内容操作化。Skill 3只压缩重复文字并保留SOLO层级或进阶方向，不重新选择或改写目标。

同一阶段同时发生的分组任务必须整合为一个活动，在活动目标、学生活动和学习产出中按组说明，不得编号成多个顺时活动。

组织形式只允许：全班集体干预、同质小组干预、异质小组干预、个体干预。“综合应用”和“学习站”只能描述活动功能或路径安排，不能作为组织形式。

### 6. 输出简短审核表

审核表固定为八行，列为：

`检查项目 | 状态 | 发现的问题 | 修改建议`

通过项的问题和建议均写“—”。不要再输出逐条子规则通过清单。

## 教师可读性要求

- 使用一线教师熟悉的“目标、活动、支架、学习产出、评价”等词语。
- 说明学生实际做什么、教师或同伴如何支持、最终形成什么成果。
- 删除设计提示、schema 名称、内部追溯说明和重复内容。
- 默认隐藏学生姓名；只有 `integration_preferences.show_student_names=true` 时才显示。
- 检查报告置于方案末尾，不打断方案正文。

## 输出前自检

- 学生诊断结果是否位于教学情境与条件之前？
- 是否以一个“诊断任务”区块完整复制上游诊断任务设计，而没有拆成多个字段？
- 班级诊断总述是否完整覆盖四项信息？
- 分层进阶目标表后是否原样保留最近发展目标说明？
- 审核表是否恰好八行且顺序正确？
- 是否根据最严重审核状态设置整体状态？
- 是否保留共同目标和分层目标？
- 教师版是否隐藏了“对课堂教学设计的构想”和“总体教学路径”？
- 并行分组是否只计一次时间且只形成一个顺时活动？
- 活动名称、时长和组织形式是否位于表格上方？
- 教师活动、学生活动、AI辅助是否只位于“活动过程”内部？
- 教师端是否删除了单独的会话圈栏目？
- 是否误加了干预成效评价？若有，删除。
- 是否对上游实质内容进行了未经授权的修改？若有，撤销并改为审核问题。
