# 班级 SOLO 聚合诊断与精准教学建议

## 任务边界

完成以下工作：

1. 读取统一结构的 `precision_teaching_context`；
2. 直接聚合 `solo-student-diagnosis-feedback` 的学生个体诊断结果；
3. 统计 P/U/M/R/EA 五级人数、比例和名单；
4. 分析班级整体及各非空层级的思维结构、障碍和进阶方向；
5. 基于诊断结果与精准教学目标提出教学重点、难点、分组方案和后续干预设计依据。

不要读取原始学生作答重新判断层级，不得修改上游诊断结果。不要生成具体学习活动、课堂组织流程、形成性评价、逐字师生话术、AI 话术或详细支架脚本；这些内容由下游精准干预设计 Skill 完成。

## 输入门槛

运行前核对 `assets/class-diagnosis-input.schema.json`。必须有：

- `precision_teaching_context`：学科、年级、教材版本与章节、精准教学主题、目标和内容；
- `student_diagnosis_results`：至少一名学生的 Skill 2 机器可读诊断结果。

每名学生必须有唯一的 `student_id`。若出现重复编号、缺少必需字段、非法层级，或结果不是 Skill 2 可识别结构，先说明问题并请用户修正；不要猜测或补造。

## 执行流程

### 1. 建立教学语境

提取学科、年级、教材版本、精准教学主题、目标和内容。后续教学重点、难点和干预设计依据必须具体回应这些信息。

### 2. 锁定上游结果

记录每名学生的原始层级、判断依据、思维结构、主要障碍、进阶目标和学习策略。后续只能聚合、归纳和引用这些结果，不能依据自己的理解升降学生层级。

### 3. 统计五级分布

按 P、U、M、R、EA 固定顺序统计人数、比例和学生名单，包括人数为 0 的层级。人数之和必须等于输入学生总数，名单不得重复或遗漏。

输入来自本地 JSON 文件时，优先运行：

```text
python scripts/aggregate_distribution.py <input.json>
```

若输入直接出现在对话中，则自行计算并用两种方式复核：五级人数求和、五级名单合并去重。比例按 `人数 ÷ 班级总人数` 计算；机器结果保留 0—1 数值，教师表格显示百分比。

### 4. 形成班级与层级诊断

- 指出主要集中层级，可并列，不强行指定唯一层级；
- 概括全班能够怎样组织信息、主要断点在哪里、差异是否明显；
- 只对有学生的层级生成详细分析；
- 典型表现、依据和障碍来自个体结果，可压缩共同点，但不能虚构学生表达；每个非空层级紧接给出一句可操作的教学建议，避免与后续依据重复展示；
- 引用学生原话时使用上游证据中的原句并标明学生与定位。

层级标签在师生可读报告中必须写成“代码（中文全称）：本次任务中的通俗含义”，不能只写 P/U/M/R/EA。

### 5. 确定教学重点与难点

先完整阅读 `references/solo-progression-support-rules.md`。

- 教学重点：依据班级多数或具有代表性的进阶方向，明确下一阶段要发展的认知结构；
- 教学难点：依据反复出现的进阶障碍，明确最需要突破的关键思维问题；
- 二者都必须分别写出诊断依据和精准教学目标依据。

不要仅用人数最多的层级机械决定重点，也要考虑障碍的代表性、对后续学习的影响和教学目标的重要性。

### 6. 生成分组建议

完整阅读 `references/grouping-rules.md`。同质分组用于集中补救或相近目标进阶；异质分组只在互补思维能够支持共同任务时提供，不能按层级机械配额。两种分组是相互独立的备选方案，不要求同时实施。每个小组必须有反映本轮共同需要或协作任务的简短组名，不用层级或能力高低给学生贴标签；名单置于组名之下，随后简述共同点或互补依据及教学建议。

同质方案必须恰好覆盖本次参与诊断的全部学生。若提出异质方案，也必须恰好覆盖同一批学生；若不能形成有教学价值的全员异质方案，则不输出异质小组，并简要说明本轮不建议的理由。两个方案内部均不得重复或遗漏学生；只有全班仅一人时可形成单人支持安排。

教师端呈现遵循以下压缩规则：

- 多个异质组执行同一任务时，只写一次共同任务、合作规则和共同产出，再用名单表列出各组学生及其互补依据；
- 各组承担不同任务时，用一张表分别列出组名、名单、任务重点和互补依据，共通要求仍只写一次；
- 不得为每组机械重复相同的分组理由、合作方向和共同产出。

### 7. 生成后续干预设计依据

依据 `references/solo-progression-support-rules.md`，把共同障碍和进阶目标整理为下游方案设计所需的决策输入。每条必须包括：

- 面向学生；
- 诊断发现；
- 需要促进的认知变化；
- 后续设计需要满足的条件。

优先按共同需求形成对象群体，避免一人一项。设计条件可以说明任务入口、关系加工、支架强度、迁移要求或课堂条件，但不得给出具体活动、活动步骤、产出模板、组织流程或评价方案。分组名单仍保留在上一模块，因为其生成依赖个体诊断记录；下游智能体决定是否采用并将其转化为课堂路径。

### 8. 输出并自检

先按 `assets/class-diagnosis-output-template.md` 输出教师可读 Markdown，再输出一个标记为 `json solo_class_diagnosis` 的有效 JSON 代码块。JSON 必须符合 `assets/class-diagnosis-output.schema.json`。

交付前检查：

- 输入学生总数与五级人数总和一致；
- 每名学生在分布名单中只出现一次；
- 输出层级与 Skill 2 原始层级逐人一致；
- 五个层级均出现在分布表，详细分析只覆盖非空层级；
- 典型依据可追溯，没有虚构学生表达；
- 教学重点和难点同时具有诊断依据与教学目标依据；
- 分组依据包含障碍和进阶目标，不只看层级；
- 异质分组具有明确合作目的和可追溯的资源互补，不按层级机械配额；
- 同任务异质组的共同说明只呈现一次，各组名单完整且不重复相同段落；
- 同质方案和任何已提出的异质方案都各自完整、无重复地覆盖所有参与诊断学生；不适合异质方案时明确说明，不强行凑组；
- 每条干预设计依据均含面向学生、诊断发现、认知变化和设计条件；
- 没有提前生成具体活动、形成性评价或课堂流程；
- 没有形成一人一项的碎片化建议；
- 师生可读层级均含代码、全称和当前任务含义。

## 资源

- `references/solo-progression-support-rules.md`：形成教学重难点和干预建议前必须读取；
- `references/grouping-rules.md`：生成同质或异质分组前必须读取；
- `examples/cross-disciplinary-example.md`：需要校准输出粒度和跨学科表达时读取；
- `scripts/aggregate_distribution.py`：从 JSON 输入确定性统计五级分布；
- `scripts/validate_contract.py`：修改本 Skill 后执行契约与不变量验证；
- `tests/behavior-cases.json`：人工或模型前向测试用的边界案例。
