# 班级 SOLO 聚合诊断与精准教学建议

## 任务边界

完成以下工作：

1. 读取统一结构的 `precision_teaching_context`；
2. 直接聚合 `solo-student-diagnosis-feedback` 的学生个体诊断结果；
3. 统计 P/U/M/R/EA 五级人数、比例和名单；
4. 分析班级整体及各非空层级的思维结构、障碍和进阶方向；
5. 基于诊断结果与精准教学目标提出教学重点、难点、分组方案和后续干预设计依据。

不要读取原始学生作答重新判断层级，不得修改上游诊断结果。不要生成具体学习活动、课堂组织流程、形成性评价、逐字师生话术、AI 话术或详细支架脚本；这些内容由下游精准干预设计 Skill 完成。

## 输入门槛

运行前核对 `assets/class-diagnosis-input.schema.json`。必须有：

- `precision_teaching_context`：学科、年级、教材版本与章节、精准教学主题、目标和内容；
- `student_diagnosis_results`：至少一名学生的 Skill 2 机器可读诊断结果。

每名学生必须有唯一的 `student_id`。若出现重复编号、缺少必需字段、非法层级，或结果不是 Skill 2 可识别结构，先说明问题并请用户修正；不要猜测或补造。

## 执行流程

### 1. 建立教学语境

提取学科、年级、教材版本、精准教学主题、目标和内容。后续教学重点、难点和干预设计依据必须具体回应这些信息。

### 2. 锁定上游结果

记录每名学生的原始层级、判断依据、思维结构、主要障碍、进阶目标和学习策略。后续只能聚合、归纳和引用这些结果，不能依据自己的理解升降学生层级。

### 3. 统计五级分布

按 P、U、M、R、EA 固定顺序统计人数、比例和学生名单，包括人数为 0 的层级。人数之和必须等于输入学生总数，名单不得重复或遗漏。

输入来自本地 JSON 文件时，优先运行：

```text
python scripts/aggregate_distribution.py <input.json>
```

平台已有确定性统计时无需模型重复计算；独立处理输入时核对五级人数求和及名单合并去重。比例按 `人数 ÷ 班级总人数` 计算；机器结果保留 0—1 数值，教师表格显示百分比。

### 4. 形成班级与层级诊断

- 教师页面按交互情况、班级整体学情、学生分层学情、教学干预建议组织；各字段言简意赅，优先一两句，不重复叙述。
- 每个非空层级用2—4句概括本任务中的实际表现，包括学生说了什么、怎样理解或回应及有依据的差异；区分学生独立提出、在AI追问后提出和仅确认AI说法，不把后两者都写成自主掌握；不能以少数学生的表现概括为全体。基于真实表达归纳具体困难，不把层级定义当作困难，不推断未经证实的学科事实或心理原因。
- 教学建议参照教师提供的SOLO进阶设计依据，根据真实障碍和教学目标，在 teaching_design 中分别填写 content（具体材料或内容）、task（学生如何加工或回应）、scaffold（最小必要支持），每项一句；P层先以一个可完成的入口帮助学生独立回应，不一步要求完整解释或评价；U层优先扩展不同且相关的信息，不强求完整关系链；M层根据任务组织相关信息之间的关系；R层视教学目标和材料，提供可选择的新情境、条件变化或边界检验方向。各阶段可灵活进阶，不把支持强度当作学生学习上限。
- 在任何学科中，依据任务判断需要解释的关系：可以是数量、空间、逻辑、实验、因果或文本关系，不一律套用因果链；先后出现不等于因果，不把未经学生或材料验证的关联写成既定事实。未提供比较材料时，将其表述为可选材料，不声称已经存在。
- 只有同层级学生确有明显不同、需要不同教学支持时，才增加第二个问题；不得为了覆盖每个人强行分类，也不罗列每名学生的问题。
- difficulty_groups 中每项 problem_label 为18字以内短语，problem_description 一句话，student_ids 只包含有依据的学生，teaching_suggestion 一句话；difficulty 保留相同描述供既有格式使用。依据个体 progression.main_obstacle，不从层级标签推测。
- 合并含义相近的问题，避免不同表述重复；个别情况放在个体关注或个体诊断，不挤进层级概览。学生名单和1—2位代表学生的分析用于教师按需查看。
- individual_attention 仅在学生原始表达有明确依据时记录身体不适、参与状态、情绪表达、学习支持、新思路或安全关注；情绪表达仅用于学生明确说出的感受，不由拒答、催促或无关发言推断情绪。身体不适与参与行为不当作心理状态。原话逐字摘录，描述可观察事实与教师下一步，不诊断、不贴标签，无依据时返回空数组。明确即时人身安全风险提示教师及时关注。程序在一次修正后仍无法核实的附加提醒会省略并标注需人工核对，不据此阻断其余有效班级分析。
- 班级概览提炼主要集中层级、共同表现和关键断点，详细分析只覆盖非空层级。
- 典型表现、依据和障碍来自个体结果，可压缩共同点，但不能虚构学生表达；教学建议按 content、task、scaffold 分别填写，避免重复展示；
- 每个非空层级选取一至两名不同的代表学生，供平台结合其个体诊断简要展示层级判断依据和具体困难；选择能体现该层级特点的学生。结构化证据由程序从该层级真实个体诊断复制原句、定位和解释；模型定位错误时在同一学生已核验证据中选取，学生错误时在本层级重新选取代表，均不生成新证据。该层没有可核验证据时须先更新个体诊断。教师展示以分析为主，不直接堆砌原话。

层级标签在师生可读报告中必须写成“代码（中文全称）：本次任务中的通俗含义”，不能只写 P/U/M/R/EA。

### 5. 确定教学重点与难点

先完整阅读 `references/solo-progression-support-rules.md`。

- 教学重点：依据班级多数或具有代表性的进阶方向，明确下一阶段要发展的认知结构；
- 教学难点：依据反复出现的进阶障碍，明确最需要突破的关键思维问题；
- 二者都必须分别写出诊断依据和精准教学目标依据。

不要仅用人数最多的层级机械决定重点，也要考虑障碍的代表性、对后续学习的影响和教学目标的重要性。

### 6. 生成小组教学建议

阅读 references/grouping-rules.md。先按 SOLO 层级分组，同层人数较多时依据实际困难细分，不跨层级凑组。人数少时保留实际人数，供教师灵活安排；每名学生恰好出现一次，完整名单由程序核对。

**组名从学习任务提炼核心活动，采用2—6字短语加“组”**，如“方法比较组”“证据检验组”。名称说明学生要做什么，不使用学生问题、直接套用层级名称或截取任务第一句话；示例不能脱离实际任务照搬。

level_group_name 保存对应 teaching_design.task 的短名称；具体困难组的 group_name 同样依据学习任务。每组依次呈现学情（分组依据）、完整学习任务、共同教学支持、学生名单。相同任务和支持只介绍一次，其下按第一组、第二组列出名单。不输出组内逐人支持建议。

当前平台采用同质分组，heterogeneous_groups 返回空数组；其余兼容字段遵循运行时 Schema，不额外设计异质方案。

### 7. 生成后续干预设计依据

依据 `references/solo-progression-support-rules.md`，把共同障碍和进阶目标整理为下游方案设计所需的决策输入。每条必须包括：

- 面向学生；
- 诊断发现；
- 需要促进的认知变化；
- 后续设计需要满足的条件。

优先按共同需求形成对象群体，避免一人一项。设计条件可以说明任务入口、关系加工、支架强度、迁移要求或课堂条件，但不得给出具体活动、活动步骤、产出模板、组织流程或评价方案。分组名单仍保留在上一模块，因为其生成依赖个体诊断记录；下游智能体决定是否采用并将其转化为课堂路径。

### 8. 输出并自检

只输出符合运行时 Schema 的一个完整 JSON 对象；assets/class-diagnosis-output.schema.json 为完整契约，平台提供精简 Schema 时由程序补齐统计、名单及追溯字段，不输出 Markdown、代码围栏或另附文字报告。教师页面与导出报告由平台根据校验后的字段排版。`assets/class-diagnosis-output-template.md` 仅说明平台展示结构，不要求模型重复撰写。

交付前检查：

- 输入学生总数与五级人数总和一致；
- 每名学生在分布名单中只出现一次；
- 输出层级与 Skill 2 原始层级逐人一致；
- 五个层级均出现在分布表，详细分析只覆盖非空层级；
- 典型依据可追溯，没有虚构学生表达；
- 教学重点和难点同时具有诊断依据与教学目标依据；
- 同质分组先按层级，同层人数多时结合实际困难；组名概括任务，任务正文完整；
- 同质方案完整、无重复地覆盖所有参与诊断的学生；
- 每条干预设计依据均含面向学生、诊断发现、认知变化和设计条件；
- 没有提前生成具体活动、形成性评价或课堂流程；
- 没有形成一人一项的碎片化建议；
- 师生可读层级均含代码、全称和当前任务含义。
